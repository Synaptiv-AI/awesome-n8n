# Design: n8n-docs-sync

**Date:** 2026-03-07
**Status:** Approved

## Problem

The `n8n-docs-llms.txt` file in this repo is a static snapshot from June 2025 (pre-n8n 2.0), manually produced by Synaptiv AI with no tooling to reproduce or update it. n8n's documentation evolves with every release (~biweekly), so the file goes stale quickly.

## Discovery

n8n officially publishes LLM-ready documentation at build time:

| File | URL | Size |
|---|---|---|
| `llms.txt` | `https://docs.n8n.io/llms.txt` | ~125 KB (index/TOC) |
| `llms-full.txt` | `https://docs.n8n.io/llms-full.txt` | ~4.0 MB (complete docs) |

These are generated by the `mkdocs-llmstxt` plugin (v0.3.1) on every deploy and always reflect the latest docs.

The Synaptiv file (~1.4 MB) is a **processed subset** of the official ~4.0 MB file with these transformations:
- Prose condensation via LLM (~58-66% of size reduction)
- Release notes removed (~20% of reduction)
- Template/example link blocks stripped (~8%)
- Repeated boilerplate deduplicated (~3-4%)
- Section delimiters added (`----------------------------------------`) for RAG chunking
- Structured intro summary prepended
- Standardized section templates added to node docs

## Solution

A Go binary (`n8n-docs-sync`) that downloads the official `llms-full.txt` and processes it through a pipeline, using `claude -p` for prose condensation. Runs weekly via GitHub Actions, creating PRs when content changes.

## Pipeline Architecture

```
docs.n8n.io/llms-full.txt (4MB)
    |
    v
[Fetch] -- ETag check -> skip if unchanged
    |
    v
[Parse] -> ~1,350 Section structs with Type classification
    |
    v
[Filter] -> ~1,000 sections (release notes removed, boilerplate stripped)
    |
    v
[Condense] -> ~1,000 sections processed via claude -p (cached by content hash)
    |
    v
[Format] -> Add delimiters, intro, footer
    |
    v
n8n-docs-llms.txt (~1.4MB)
```

### Stage 1: Fetch

- HTTP GET `https://docs.n8n.io/llms-full.txt`
- Store and check ETag/Last-Modified headers to skip processing when unchanged
- Store raw download for comparison

### Stage 2: Parse

Split the file into `Section` structs by `#` headers. Classify each section:

| Pattern | Type |
|---|---|
| `# <Name> node` | `node-doc` |
| `# <Name> credentials` | `credential` |
| `# n8n@X.Y.Z` or contains "release" | `release-note` |
| `# API` or contains `/api/` paths | `api-ref` |
| Everything else | `general` |

### Stage 3: Filter

Remove entire sections:
- `release-note` type sections

Strip patterns within remaining sections:
- "Templates and examples" blocks (template link lists with "View template details")
- "Parameter resolution in sub-nodes" boilerplate (repeated ~71 times)
- "Human-in-the-loop for AI tool calls" boilerplate (repeated ~23 times)
- "What to do if your operation isn't supported" boilerplate (repeated ~153 times)

### Stage 4: Condense

Fan out sections to `claude -p` with type-specific prompts via a worker pool.

**Invocation:**
```bash
echo "<section_content>" | claude -p "<condensation_prompt>"
```

**Prompts by type:**

- **node-doc:** Condense into terse structured bullet points. Use `###` sub-headers for operation groups. Standardize verbs. Remove redundant context. Keep all parameter names, types, and valid values.
- **credential:** Condense into concise step-by-step instructions. Keep all required field names, URLs, and configuration values.
- **general:** Condense to essential information. Preserve all code examples, configuration values, and API endpoints verbatim.
- **api-ref:** Keep all endpoint paths, methods, parameters, and response schemas. Remove redundant descriptions.

**Quality guardrails:**
- If condensed output is >80% of input size, re-run with stricter prompt
- If condensed output is <10% of input size, flag for review
- Code blocks must be preserved verbatim

**Caching:**
- `.cache/` directory with `{sha256_of_raw_section}.txt` -> condensed output
- On each run, check cache before calling `claude -p`
- Subsequent runs only re-condense sections whose source content changed

**Concurrency:** Worker pool with configurable concurrency (default 5).

### Stage 5: Format

- Prepend structured intro summary (core concepts, node overview, best practices, workflow patterns)
- Insert `----------------------------------------` delimiters between every section
- Append footer

### Stage 6: Output

Write to `n8n-docs-llms.txt` (or custom path via `--output` flag).

## CLI Interface

```bash
# Full run
n8n-docs-sync

# Dry run (show what would change, don't write)
n8n-docs-sync --dry-run

# Skip LLM condensation (for testing)
n8n-docs-sync --no-condense

# Custom output path
n8n-docs-sync --output ./custom-path.txt

# Control LLM concurrency
n8n-docs-sync --concurrency 3
```

## Project Structure

```
cmd/
  n8n-docs-sync/
    main.go              # CLI entry point (flag parsing, orchestration)
internal/
  fetch/
    fetch.go             # HTTP client with ETag caching
  parser/
    parser.go            # Split llms-full.txt into typed sections
  filter/
    filter.go            # Remove release notes, templates, boilerplate
  condense/
    condense.go          # Worker pool for claude -p invocations
    cache.go             # Content-hash based section cache
    prompts.go           # Condensation prompts by section type
  formatter/
    formatter.go         # Add delimiters, intro summary, footer
.github/
  workflows/
    sync-n8n-docs.yml    # Weekly GitHub Actions workflow
go.mod
go.sum
```

**Dependencies:** Standard library only (`net/http`, `os/exec`, `crypto/sha256`, `flag`, `strings`, `sync`).

## GitHub Actions Workflow

**File:** `.github/workflows/sync-n8n-docs.yml`

**Triggers:**
- Cron: weekly on Monday at 08:00 UTC
- Manual: `workflow_dispatch`

**Steps:**
1. Checkout repo
2. Set up Go
3. Install `claude` CLI
4. Restore `.cache/` from `actions/cache`
5. Run `n8n-docs-sync`
6. Save updated `.cache/`
7. If `n8n-docs-llms.txt` changed, create/update PR on branch `docs/sync-n8n-docs-YYYY-MM-DD`

**Secrets required:**
- `ANTHROPIC_API_KEY` — for `claude -p` in CI

**PR behavior:** If a PR from a previous run exists and wasn't merged, update the existing branch instead of creating a duplicate.

## Estimated Runtime & Cost

| Scenario | Time | LLM Cost |
|---|---|---|
| First run (all ~1,000 sections) | ~10-15 min | ~$1-3 |
| Subsequent run (~50 changed sections) | ~2-5 min | ~$0.05-0.15 |
| No changes (ETag match) | <10 sec | $0 |
